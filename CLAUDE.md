# Neurolume — notes for Claude

Neurolume turns PyTorch (later Keras) models into an interactive WebGL viewer
in the browser. Python traces the model into a JSON **graph**; a TypeScript +
three.js frontend draws it. The roadmap is `Neural Network Visualiser – Project
Plan.md` (phases 0–6, with checkboxes); read the relevant phase before starting
new feature work, and tick boxes only when their "Done when" criteria pass.

More detail lives next to the code:
- `python/neurolume/CLAUDE.md` — Python package: adapters, schema, server, System
- `frontend/CLAUDE.md` — viewer: layout, rendering, interaction, themes
- `tests/CLAUDE.md`, `examples/CLAUDE.md`, `scripts/CLAUDE.md`

## Working here

- **Start from the CLAUDE.md files, not the code.** Each one has a code map
  (functions in file order) and a "where to change what" table; open only the
  function you need (grep its name) rather than reading whole files.
- **Be lazy with code (user preference).** The code base is getting large: write
  only what the change needs, reuse existing helpers, don't add options,
  fallbacks or abstractions nobody asked for, and delete code a change makes
  dead. Prefer a small edit to a new function, and a new function to a new module.
- Keep the CLAUDE.md files current when behaviour or structure changes (one or
  two lines, in the right file); they are what the next session reads.

## How the pieces connect

```
model + sample ───────► adapters/torch_adapter.py ──► Graph (schema.py, pydantic)
System (system.py) ─────► many graphs merged, one group per network ─┘
Graph ──► server.py (FastAPI: GET /api/graph, serves static/) ──► frontend reads /api/graph
```

The graph schema is the only contract between Python and the frontend.
Frontend code must never know about PyTorch; Python must never know about rendering.

## Commands (Windows, PowerShell or Git Bash)

| Task | Command |
| --- | --- |
| Python tests | `.venv/Scripts/python.exe -m pytest -q` |
| Frontend tests / typecheck | in `frontend/`: `npx vitest run`, `npx tsc` |
| Build viewer into the package | `scripts/build_frontend.ps1` (always run after frontend changes) |
| Regenerate TS schema | `.venv/Scripts/python.exe scripts/generate_schema_ts.py` |
| Run an example | `.venv/Scripts/python.exe examples/system.py` |
| Live frontend dev | `neurolume.show(..., port=8000)` + `npm run dev` in `frontend/` |

## Environment gotchas

- The venv was made with **uv** and has no pip: install with
  `uv pip install --python .venv/Scripts/python.exe <pkg>`. torch is the CPU wheel
  (`--index-url https://download.pytorch.org/whl/cpu`). Python is 3.14.
- **Node** is at `C:\Program Files\nodejs` but may not be on PATH in this shell.
  Bash: `export PATH="/c/Program Files/nodejs:$PATH"`; PowerShell:
  `$env:Path = "C:\Program Files\nodejs;" + $env:Path`.
- PowerShell is 5.1: `Set-Content -Encoding utf8` writes a **BOM**, which breaks
  `package.json`. Edit files with the Edit/Write tools, or Python with
  `newline="\n"`.
- `python/neurolume/static/` is generated by the build script; never edit it.
  If the viewer shows a **white page**, the static folder is half-copied:
  rerun the build script (it now verifies every referenced asset exists).
- Don't filter build output down to "built in" — you'll hide copy errors.

## Checking the viewer visually

Headless Edge can screenshot the real viewer (WebGL via SwiftShader):

```powershell
& "C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe" --headless=new `
  --enable-unsafe-swiftshader --window-size=1600,900 --virtual-time-budget=3000 `
  --user-data-dir="<scratch>\profile" --screenshot="<scratch>\shot.png" http://127.0.0.1:8765/
```

- Serve a model first with `neurolume.show(model, x, port=8765, open_browser=False, block=True)`
  (run it in the background; kill it by port afterwards).
- Theme: add `--force-dark-mode --blink-settings=preferredColorScheme=0` for
  dark, `preferredColorScheme=1` for light.
- Headless can't click, hover, scroll or animate. To check a state such as an
  open inspector or an opened network, temporarily add a `location.hash` hook
  in `main.ts` marked `// TEMP`, rebuild, screenshot, then delete it and rebuild.
- Stop screenshot servers **before** running the build script.

## Rules from the plan (still apply)

1. Schema changes bump `SCHEMA_VERSION`, update pydantic models, regenerate `schema.ts`.
2. No framework imports at module top level outside `adapters/`; `import neurolume`
   must work without torch (enforced by `tests/test_imports.py`).
3. New layer types get a test model and a schema test.
4. Prefer simple, readable code: this is also a teaching resource.

## User preferences learned so far

- Wants a polished, "presentation-ready" look; references dense glowing
  neural-net renders (tall framed panels, organic tangled edges).
- Rejected: continuous animations (GPU cost on an Intel iGPU), saturated blue
  backgrounds, the generic "AI app" look (Inter, rounded pills, glass, purple).
  Liked: high-contrast dark/light themes, colourmap picker, a technical-schematic
  style (IBM Plex Sans/Mono, 2px corners, hairlines; see `frontend/CLAUDE.md`).
- Visual tuning values (edge opacity, zoom thresholds) were chosen with the
  user; ask before changing them.
